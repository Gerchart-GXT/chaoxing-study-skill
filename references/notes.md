# 笔记与汇报

边做边整理。每完成一个小节立刻写盘，不要攒到最后——中途断开也不会丢。

## 文件组织

```
notes/
  00-总览.md           索引：章节、小节、得分、存疑汇总
  01-<章名>.md
  02-<章名>.md
  ...
```

章节文件名用两位序号 + 章名，按课程顺序。章名**不要**带学校、单位、课程 id。

## 每小节的结构

```markdown
## <编号> <小节名>

- 视频：已播完（<时长> 秒）
- 测验：已提交，**<得分> 分**
- 状态：已完成 [OK] / 存疑

### 题目

**1. 【Single Choice】<题干>**

- A <选项>
- B <选项>
- C <选项>
- D <选项>

作答：**C**（正确，33.3）

**2. 【Multiple Choice】<题干>**

作答：**A、B、C**（正确，33.4）

**3. 【True or False】<题干>**

作答：**False**（**答错**，正确答案未公开）
存疑：两次提交均判错；按教材应为 True，但平台判 False。

### 视频内嵌题

题干：<题干>

- A、对
- B、错

作答：**A、对**
```

要点：

- 题干与选项照抄页面，不改写、不省略。
- 作答记录**实际提交**的选项，同时记录平台判定（正确/答错）与得分。
- 答错的题：只写"平台判定错误"，加上"标准答案未公开"。不要编造正确答案。
- 视频内嵌题单独一节，与章节测验分开。

## 总览页

```markdown
# <课程名> 题目与答案总表

范围：<N> 个章节、<M> 个小节，共 <X> 道测验题 + <Y> 道内嵌题。

| 章节 | 小节数 | 测验得分 |
|---|---|---|
| [01 绪论](01-绪论.md) | 5 | 100 / 100 / 100 / 100 / 100 |
...

## 存疑清单

| 小节 | 题号 | 题型 | 情况 |
|---|---|---|---|
| 3.8 | 2 | 多选 | 两次提交均判错，标准答案未公开 |
```

## 汇报

结束时给一次总汇报，包含：

1. 完成情况：目录里已完成 / 总数，用 `cx.mjs verify` 的返回值，不凭印象。
2. 分数分布：满分 / 90 分以上 / 60–90 / 60 以下的题次。
3. 存疑清单：逐条列出，说明为什么存疑。
4. 未做的事：明确说哪些没做（通常是考试、需人脸的环节）。

## 不要把存疑当失败

存疑不阻塞流程，只是记录。汇报里如实列出即可，不要为了"全对"去反复重试或猜答案。

## 状态文件配合

每完成一节：

```bash
cx.mjs record --name "<小节名>" --data '{"video":"done","score":100,"verified":true}'
cx.mjs record --name "<小节名>" --data '{"score":66.7,"verified":true,"doubtful":["2:两次提交均判错"]}'
```

`cx.mjs summary` 汇总出待处理、已核验、存疑三类，用来交叉检查笔记有没有漏。
